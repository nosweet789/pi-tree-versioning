# Pi Tree Versioning

[English](README.md)

让文件历史跟随 pi 的原生会话树：每轮处理结束后保存检查点，查看文件改动，并在树导航或分叉后恢复已保存的文件。界面支持英文和简体中文。

**文件恢复开启时（默认），`/tree` 或 `/fork` 会覆盖尚未入快照的改动。** 使用前请阅读[恢复规则](#恢复文件)。

## 安装

已验证宿主：**@earendil-works/pi-coding-agent 1.5.2**。环境中需要 Git、Node.js 和 npm 命令行客户端。

```sh
pi install git:github.com/nosweet789/pi-tree-versioning
```

pi 会下载扩展并安装依赖。随后在要处理的 Git 项目中启动 pi，或在已有会话中执行 `/reload`。

若只想在本次运行中试用：

```sh
pi -e git:github.com/nosweet789/pi-tree-versioning
```

临时加载保持安装声明不变。下载的文件会缓存，会话历史、快照和已保存的扩展偏好仍按正常方式存储。

`pi install` 会向用户设置添加包声明。加上 `--local` 可使用项目的 `.pi/settings.json`，项目资源在获得信任后加载。其他已有设置会保留。

### 更新或移除

```sh
pi update git:github.com/nosweet789/pi-tree-versioning
pi remove git:github.com/nosweet789/pi-tree-versioning
```

使用与安装时相同的作用域；项目安装需加 `--local`。单独运行 `pi update` 更新的是 pi 本身。若要固定扩展版本，在 Git 来源末尾加上 `@<标签或提交号>`，使用仓库中已存在的标签或提交。移除扩展后，已保存的快照仍保留在磁盘上。

### 加载本地副本

在检出目录执行 `npm ci`，然后从工作项目中加载：

```sh
pi -e /absolute/path/to/pi-tree-versioning
```

若需持久安装，使用 `pi install /absolute/path/to/pi-tree-versioning`。请保持该目录和依赖可用，pi 会直接从本地路径加载。

## 查看改动

在 Git 工作区内启用扩展时，会采集**会话基线**，包含当时已有的未提交改动。每个完整处理轮次结束、pi 重新等待输入时保存检查点，包括中断或报错后停止的情况。中途引导（steering）、排队输入和自动重试仍属于这段连续处理。

如果会话在 Git 工作区外启动且没有已保存的文件历史，扩展会跳过文件版本功能。聊天和原生 `/tree`、`/fork`、`/clone` 照常工作，不会恢复文件。`/tree-versioning-diff` 会提示无法查看文件差异的原因。

每个检查点会生成卡片，列出变更文件及每个文本文件的增删行数。列表上方按该轮已保存的净差异汇总变更文件总数，只列出修改、新增和删除中非零的计数。文件类型变化在总结中计为修改。加粗路径和主题差异色区分文件状态、新增、删除与上下文，同时保留状态文字和 `+`/`-` 标记。使用 pi 的**展开工具输出**操作（默认 **Ctrl+O**）查看文本补丁。二进制文件显示变化摘要。没有文件改动的轮次也会保存检查点，并显示空差异卡片。

原生 `/tree` 落在文件检查点上、但当前分支没有该轮的卡片时，输入框上方会显示轮次差异预览，关闭文件恢复也能看到。使用同一个工具输出展开操作查看补丁。如果一屏放不下，可用 `/tree-versioning-diff round` 在可滚动的查看器中浏览完整差异。预览放不下完整命令时，可加宽终端。

查看当前会话分支已保存的总差异：

```text
/tree-versioning-diff
```

只读查看器比较会话基线与当前分支的已保存检查点。文件列表上方显示两个端点间有净变化的文件总数，只列出修改、新增和删除中非零的计数。文件类型变化在总结中计为修改。此后磁盘上的改动属于下文的工作区比较。

查看器像 pi 的 `/tree`、`/resume` 一样在底部输入区打开，关闭后恢复原输入和焦点。面板最多占终端半屏，内容较短或存在其他 widget 时收缩，长差异在面板内滚动。关闭提示保留在底部；键位说明过宽时，可滚动到开头查看完整说明。终端过小或其他 widget 占满输入区时，请放大窗口或减少这些 widget，以同时查看内容与操作提示。

默认按键为：**Ctrl+O** 展开补丁，**↑/↓** 滚动，**Page Up/Page Down** 翻页，**Escape** 关闭。自定义 pi 快捷键同样生效。使用 `/tree-versioning-diff help` 查看帮助；RPC、print 或 JSON 模式可通过 `session_diff` 的 `scope: "session"` 查询。

卡片展示采集时保存的比较结果，重开会话后按当前语言和主题渲染。卡片仅供界面展示；agent 通过下述工具主动查询的结果则正常进入模型上下文。路径和代码保留原文，终端控制字节以可见的转义形式显示。分享会话导出内容前请先检查，因为卡片可能包含源代码文本。

## 恢复文件

自动文件恢复**默认开启**。使用以下命令查看或切换：

```text
/tree-versioning-restore
/tree-versioning-restore off
/tree-versioning-restore on
```

不带参数或使用 `help` 可查看当前状态与用法。选择全局保存在 pi 数据目录下扩展自己的 `tree-versioning/preferences.json` 中，跨工作区、新会话、切换会话、重载和重启生效；新建会话**不会重置为开启**。其他已经运行的 pi 实例会在扩展运行时重新加载时读取保存的选择，例如执行 `/reload`。

恢复**关闭**时，`/tree` 和 `/fork` 保留当前磁盘文件。会话基线和检查点采集、差异卡片及查询、分叉与克隆的快照继承均照常进行。后续处理轮次记录的是实际磁盘状态，即使它与对话的历史位置不一致。

关闭会使尚未开始写入的恢复任务失效，随后开启也不会复活这些任务。开启**不会**立即恢复当前位置或补做此前的导航，只有后续导航或分叉才可能恢复文件。切换不能中断已经进行中的同步写入。

**恢复会直接采用目标快照，覆盖尚未入快照的受管理文件改动，并删除目标中不存在的受管理新文件。没有合并、额外备份或新增确认步骤。重要改动请在导航前自行备份。**

下表仅适用于已启用文件版本功能的会话。

| 操作 | 恢复开启时的文件行为 |
| --- | --- |
| 原生 `/tree` 导航成功 | 恢复实际落点对应的已保存状态 |
| 同工作区 `/fork` 成功 | 继承历史，再恢复分叉落点 |
| 同工作区 `/clone` | 继承历史，保留当前磁盘改动 |
| 启动、重载、重开或切换会话 | 读取历史或建立基线，保留当前文件 |
| 导航或分叉取消、失败，或选择当前落点 | 保留当前文件 |

检查点对应**完整处理轮次**，而不是每条消息或每次工具执行。落点没有自己的检查点时，沿其祖先路径使用最近前置检查点，或覆盖该位置的适用基线。通知会指明实际恢复的状态。恢复以 pi 的原生实际落点为准：例如选择用户消息时，会从其父节点继续。

分叉或克隆继承源会话基线，以及复制路径上的检查点；会话总差异仍从继承的基线开始比较。继承完成后，子会话独立持有快照，之后清理源历史也不影响子会话已有历史的使用。该继承适用于同一 Git 工作树。

### 操作失败时

- **偏好操作失败**：加载或保存前读取偏好失败时，报告错误并在当前运行时关闭恢复；文件历史初始化和采集仍独立进行。不覆盖损坏的偏好文件，请修正文件后重载或重试命令。如果仅写入失败，则保持此前的选择，不宣称保存成功。
- **偏好锁忙碌**：偏好保存会在 pi 进程之间串行进行。锁持续忙碌五秒时，保存失败，不覆盖其他进程的更新。写入进程异常退出可能在 pi 数据目录下留下 `tree-versioning/preferences.json.lock`；先停止所有使用该数据目录的 pi 进程，再移除该锁目录并重试。
- **采集失败**：提示本轮未记录。如果只是差异比较失败，检查点仍已记录，卡片会显示比较错误。
- **历史缺失、损坏或未覆盖目标位置**：保留文件并报告历史不可用。查询会返回错误，而不是空差异或其他分支的替代结果。
- **恢复失败**：保留原生会话落点，并提示**文件可能仅部分恢复**。若分叉已经成功，子会话也会保留。请检查文件、解决错误，再先导航离开目标位置，然后返回重试。

在旧会话中首次启用时，基线覆盖启用位置和此后新建的后代节点；更早的节点及启用前已经存在的后代节点仍不在覆盖范围内。打开或重载会话不会重试失败的恢复。

## Agent 查询工具

可以让 agent 使用以下只读工具检查恢复状态和文件历史：

- `tree_versioning_status`：无需参数，返回当前运行时生效的 `{ "restoreEnabled": true }` 或 `{ "restoreEnabled": false }`。不扫描或恢复文件，也不修改偏好；切换开关请使用上面的用户命令。
- `session_checkpoints`：列出会话基线、检查点、原生节点关联、当前位置适用的快照，以及固定的仓库覆盖范围。
- `session_diff`：比较已保存状态或当前工作区，并标明起止端点和仓库覆盖范围。

| `scope` | 起点 | 终点 |
| --- | --- | --- |
| `workspace`（默认） | 当前路径上的最近检查点，或适用基线 | 当前磁盘文件 |
| `turn` | 所选检查点的前置检查点，或适用基线 | 所选检查点 |
| `session` | 会话基线 | 当前路径上的已保存检查点 |

`turn` 可通过可选参数 `checkpointId` 选择 `session_checkpoints` 返回的 ID；省略时使用当前路径上的最近检查点。可选参数 `files` 按精确的外层工作区相对路径筛选，包含 `nested/notes.txt` 这样的内层仓库前缀，允许前置 `@`。路径是精确匹配，不是 glob 通配模式；空数组表示不选择文件。

尚无检查点时，`session` 将基线与自身比较，`turn` 则报告 `no_checkpoint`。比较所需的快照缺失或损坏时返回错误。查询保持工作区文件、原生树位置和检查点不变；如果一个 agent 轮次只执行了查询，轮次结束时仍会照常采集检查点。

工具输出限制在约 **50 KiB / 2000 行**。更大的结果会提供 `output.fullOutputPath`，指向包含完整结果的私有临时 JSON 文件。此时省略的 `files`、`checkpoints` 或 `coverage` 数据在导出文件中，并非为空；`output.totalRepositories` 给出仓库数量。

## 内层仓库

若要纳入工作区里的普通独立仓库，先设置搜索深度，再**新建会话**：

```text
/tree-versioning-repository-depth 1
/new
```

默认深度为 **0**（仅外层仓库）。深度按相对外层 Git 根目录的目录层数计算：`nested/` 为 1，`packages/example/` 为 2；经过仓库时不重新计数。命令不带参数时显示配置深度及当前会话的实际覆盖范围。设置按工作区保存在扩展自己的偏好中，不改变 Git 或 pi 设置。

新基线自动纳入深度内的**所有合格仓库**，包括父仓库忽略目录里的仓库，而不限于 agent 修改过的仓库。各仓库遵循自身的跟踪和忽略规则。卡片及查询显示覆盖的仓库路径（`.` 表示外层根目录），文件路径保留外层工作区前缀。

**纳入的仓库也参与文件恢复。** 恢复开启时，`/tree` 和 `/fork` 可能覆盖其中未入快照的受管理改动，不额外备份。`/clone` 继承覆盖范围和历史，但不恢复文件。

覆盖范围在基线创建时固定。提高或降低设置、重载、重新打开都不会改变已有会话；分叉／克隆继承源会话范围，不受当前偏好影响。旧格式会话仍只覆盖根仓库。中途创建的仓库不会自动加入；若新仓库与已保存的受管理路径相交，采集和恢复会失败，而不是将该转换当作普通文件删除。

搜索不跟随目录符号链接，不进入 Git 管理数据、子模块、内层 worktree 或重定向 Git 目录的内层仓库。搜索限制为检查 10,000 个目录条目、包含外层根目录在内的 256 个仓库，以及 30 秒的发现预算。搜索失败或触达限制时不发布部分基线。已纳入仓库缺失、不可访问、被替换或 Git 管理目录迁移时，采集失败，恢复则在任何仓库文件写入前的检查阶段失败。解决问题后再重试；仅 Git 分支或 HEAD 变化不视为仓库身份变化。

## 文件范围与存储

扩展默认管理**整个外层 Git 工作树**，即使 pi 从子目录启动也一样。已纳入的内层仓库分别遵循相同规则：

- 已跟踪文件，包括匹配忽略规则的已跟踪路径。
- 未被忽略的未跟踪文件。
- 文件新增、删除、二进制内容、可执行标志和符号链接。

被所属仓库忽略且未跟踪的文件、未纳入的内层仓库、Git 内部数据、子模块内容及外层工作树之外的路径不在范围内。符号链接保存为链接本身，不跟随目标。扩展保持 Git HEAD、分支选择和暂存区不变。

快照保存在 `~/.pi/agent/tree-versioning/<session-id>/`，设置了 `PI_CODING_AGENT_DIR` 时遵循该位置。请将 pi 数据目录及会话文件放在受管理工作树之外。持久会话在重启后保留文件历史；`--no-session` 会话随进程结束。

快照以完整副本保存在本机，由用户手动清理；跨机器同步不在支持范围内。大型工作树可能占用较多内存和磁盘，较长的恢复操作也可能暂停界面响应。并发写入与多文件恢复没有跨文件原子性保证。

## 语言

选择扩展界面的语言：

```text
/tree-versioning-language en
/tree-versioning-language zh-CN
/tree-versioning-language auto
```

使用 `/tree-versioning-language help` 查看当前偏好。选择保存在扩展自己的 `tree-versioning/preferences.json` 中，跨会话和重启生效。已有卡片会按所选语言渲染，检查点和比较结果保持原样。

`auto` 依次检查 `LC_ALL`、`LC_MESSAGES`、`LANG`，最后检查系统区域设置。简体中文区域设置（`zh`、`zh-CN`、`zh-SG` 和 `zh-Hans` 变体）选择 `zh-CN`，其他区域设置使用英文。显式指定 `en` 或 `zh-CN` 时优先采用该选择。

语言选择作用于本扩展界面。pi 原生界面沿用其自身设置；工具名、参数、状态码、文件路径和代码保持原样。
